## 9주차: Priviliege Separation

> - SFI 연산 구현 [9]
> - micro hypervisor 의 machine level이랑 process level 차이 [9] ??  

- Priviliege Separation, Least Priviliege를 왜 적용해야 하는가
    - Less valuable assets의 vuln(N>>m) → 이게 more valuable assets과 같은 영역에 있기 때문에 결국 N+m attack surface
    - 그래서 **isolation**으로 분리를 해서 **attack surface를 줄여야 한다.**

- Virtual Memory
    - 실제 물리 address가 아닌 가상화가 적용된 4KB Virtual address를 MMU로 실제 물리 메모리에 매칭
        - = 다른 프로세스에 대한 isolation는 OS가 해준다

- **사용자 프로그램에 대해서 적용 = In-Process Isolation**
    - 하나의 프로세스 내에서도 중요한/중요하지 않은 부분에 대해 영역을 구분하자
    - **1. thread마다 address space를 다르게 하자**
        - thread마다 필요한 permission이 다름 → page kernal로 들어가서 page table을 바꾸는 식으로 구현 → overhead가 큼
    - <span style="background-color:#e9d5b8">**2. Software Fault Isolation (SFI)**</span>
        - 프로그램 안의 **모듈 단위**로 다른 permission 갖기
        - 모듈마다 Code Segment, Data Segment를 묶어서 따로 **segment 메모리로 구분**
        - **`jmp`, `load`, `store` 명령어에 대해 가드 instruction 구현** <span style="background-color:#e9d5b8">**(→ 구현을 어떻게 하는가◆)**</span>
            - <span style="background-color:#e9d5b8">**2.1. Segment matching technique**</span>
            - dr1,dr2 (dedicated) 레지스터에 special값(segment ID)을 넣어둘거임 (dr2 = 현재 속한 segID)
                > 32-bit 시스템: 가상 주소는 32비트 → 2^32 = 총 4GB (0x1 0000 0000개)주소 공간  
                > Segment ID: 주소 공간을 1MB (2^22)단위로 나누어 구분  
                > 1MB = 2²⁰ bytes → **즉, 주소의 상위 12비트가 어떤 1MB 세그먼트에 속하는지를 나타냄**
            - <span style="background-color:#e9d5b8">**2.2. Address Sandboxing Technique**</span>
            - 이건 segmentID를 clear (= 0x000F FFFF masking) 해서 dr1에 넣고, dr1 or dr2  
            → **segID가 무조건 현재 segID가 됨 = Sandboxing**
                - &, or 같은 arithmetic 연산만 쓰니까 Segment matching 보다 성능상 이득
                - 하지만 trap은 안됨
            - **indirect jump**의 경우는 이런 check instruction을 안거치기 때문에, 제한을 따로 해야 함
                - r12 ← [r34] 같은 load/store 명령어 앞에 수동으로 가드를 삽입하는 방식이라
                - <span style="background-color:#e9d5b8">**2.2.1. Aligned jump = 중간으로는 못뛰게 한다**</span>
                    - **최하위 4bit clear (and r1, #0xFFFF FFF0)** = 16 (0x10)의 배수로 align
                - <span style="background-color:#e9d5b8">**2.2.2. Cross domain calls**</span>
                    - 트램펄린처럼 점프하기
-  In-Kernel Isolation
    - 리눅스, 윈도우 모두 애초에 Monolithic Kernel이라 OS의 모든 코드가 하나의 권한으로 동작함
    - 분리해서 새로 만들자 하는게 **MicroKernel**
        - 커널의 세부 기능들을 유저모드로 빼서 process isolation 해버림 → context switch해야 하니까 성능 오버헤드가 큼
    - **그럼 kernel을 조금만 고쳐서 Priviliege Separation을 해보자**
        - (Background) Nested Paging = 2번 페이징
            - 가상 머신의 메모리에 대한 isolation을 위해 EPT (Extended Page Table)가 하나 더 추가됨
            - GVA(Guest Virtual Addr) → GPA → PA
        - **1. SecPod[ATC'15]: 가상화로 구현**
            - Normal Space / Secure Space를 구분하자
            - 유저 프로세스는 커널을 신뢰하니까 code memory가 안바뀔거라 신뢰하는데, 커널은 page table을 바꿔버린다면, SFI가 무용지물이다 (???)
            - **1.1. Paging Delegation**: Page Table/중요 레지스터에 대한 업데이트는 Secure Space에서만 하도록 하자 
                - **(Nested Paging)** Page Table이 들어있는 메모리 page를 Nested page로 보호 (????)
            - **1.2. Execution Trapping**: 가상 머신에서는 특수 레지스터의 업데이트에 대해 hyperviser trap 가능
        - **2. Hilps [NDSS’17]: ARM에서도 해보자**
            - TxSZ bit: virtual space 크기를 조절하는 feature (넘어가)
                - T1SZ == 16 ➔ 2^(64-16) = 2^48 → Secure space (Out → In)
                - T1SZ == 17 ➔ 2^(64-17) = 2^47 → Normal space (In → Out)
        - **3. Nested Kernel [ASPLOS’15]**
            - X86, CR0_WP bit 사용해서 inner domain 접근 권한 제어
                - WP == 0, Follows permission bits in PTE
                - WP == 1, Permission bit 체크 안하고 무조건 Read Only 
        - **4. MINIX3 [DSN’09]: 커널 Driver를 isolation**

## 10주차: Hardware-assisted Software Security #1

> - Why Shreds is better than SFI [9,10]  
> - page group. Cfi 관련된 거 적고 차이 [10] ??

- HW feature를 사용해서 더 안전하게 구현하자
- segmentation
    - 32bit 아키텍처의 segmentation 기능을 virtual memory 대신에 사용했었다
    - segment 별로 CS, DS, SS 등의 레지스터들이 있었고, 각 segment의 base와 limit가 정의되어 있었다
    - 별도의 descriptor table에 base, limit을 적어둠 → 분리되어 있어서 addr hiding이 가능했다 = isolation
    - **1. Code Pointer Integrity (CPI)**
        - code를 가리키는 pointer들을 safe region(memory)에 넣어둠
            - 특수 메모리만 이 safe memory에 접근하는데, 이걸 gs segment로 구현을 했음
    - **2. ASLR-Guard : code pointer값을 못 알아가게 하자 (Encrypt)**
        - 암호화: 랜덤 오프셋 4바이트 + 해당 엔트리에 저장된 nonce 4바이트 → rax
        - 복호화: `%gs:8(%rax)` = `%gs + offset + 8` = `nonce` → 이걸 rax와 XOR하면 offset만 남음 → `call %gs:(%rax)` = `fn`
- ARM
    - **1. Micro-Fat Pointer [DAC’24]**
        - **ARM MPU (Memory Protection Unit)**
            - time embedded system에서는 **MMU 대신 MPU**를 사용 → pysical address를 몇개의 region으로 나눠서 정의 가능
            - **region = base + size로 정의됨** → permission 설정이 가능함
            - 하지만 region은 연속적이여야 하고, 개수가 제한적임(e.g. 8, 16)
        - **ARM LSU (Load and Store Unprivileged)** 메모리 명령어
            - 실제 프로세스 모드와 상관없이, LSU 메모리 명령어를 사용하면 User mode에서 사용하는 것 같은 효과를 부여함
                - e.g. `LDRT`, `STRT` 명령어
        - **ARM TT (Test Target)**
            - MPU region Num을 반환해줌
                - `index(p)` = `TT(p) & 0x000000FF` = TT의 하위 1byte = MPU region number
                - `size(p)` = `size_map[index(p)]` = size_map의 region number 내용이 size임
                - `base(p)` = `(p / size(p)) * size(p)` = ???
    - **2. ILDI [DAC’17]**
        - **ARM PAN (Privileged Access Never)**: 커널모드로 동작하는 코드가 safe region(=유저 영역)에 접근하는 것을 막음
            - Safe region = unprivileged 데이터를 위한 공간 (보호 대상)
            - PAN = 1 (Privileged Access Never): 커널(EL1)이 unprivileged 메모리 영역에 접근할 수 없음
        - **LSU (Load and Store Unprivileged)** 메모리 명령어(LDTR, STTR)로 접근하도록 해서, PAN=1이라도 괜찮
- <span style="background-color:#e9d5b8">**ARM Paging**</span>
    - (문제) page table entry를 바꿀려면: kernel로 진입, 최종 entry까지 PT 순회, TLB 업데이트 필요
    - **1. ARM Domain 기능**
        - first level page table entry에 4bit (0~15)로 page grouping 넘버(=domain)를 넣어둠
        - **DACR(Domain Access Control Register)**(32bit)를 2bit 씩 나눠서 15개 domain 관련 그룹 설정 가능함 
            - `00` = no access, `01` = client, `11` = manager
            - 여러개 페이지에 대해 한번에 접근 제어가 가능한 것
            - DACR 레지스터를 업데이트 하는거니까 TLB 업데이트도 할 필요 없음
        - <span style="background-color:#e9d5b8">**Shred [S&P'16]**</span>
            - (In-process isolation) DACR로 shred(thread 내부 작은 code block)에 대한 exclusive memory 권한 부여
            - `shred_enter`: **DACR**을 00 → 11 변환
            - `shred_exit`:  **DACR**을 11 → 00 변환
    - **2. Intel Protection Keys** = Domain과 같은 기능
        - 똑같이 page table entry에 **page grouping용 Key(4bit)**를 넣어둠 (key = domain)
        - **RKRU (Protection key rights register)** = ARM의 DACR (Domain Access Control Register)
            - DACR은 permission bit를 따를건지에 대한 것만 있고, **PKRU는 직접적인 권한을 부여함 (RW, RO, NA)**
            - DACR은 커널에서만 접근 가능하고, PKRU는 `WRPKRU`, `RDPKRU`으로 **유저레벨에서 접근 제어 가능**
            - ERIM [Usenix Security’19]
    - **3. EPK [ATC’22]:** 지금 도메인 개수가 16개 밖에 안되니까 이를 확장해보자
        - (Nested Paging) Extended Protection Key as the domain ID
        - `Domain ID = EPT-index (0~511) + pkey (1~15)` → 곱하기여야 하는거 아닌가??

> Why Shreds is better than SFI  
- **SFI (Software Fault Isolation)**
    - jmp, load, store 명령어 앞에 **가드 instruction을 삽입**해야 하며, 이는 모든 메모리 접근/점프마다 오버헤드를 발생
    - **간접 접근(indirect jumps)**의 경우 특별한 handling이 필요하므로 오버헤드가 더 커짐
    - 보안 검증은 **컴파일/삽입 단계에 의존**하므로 우회가 가능함
    - **segment 단위**로 주소 공간을 나누기 때문에, `1MB` 단위의 고정 구획 필요
- **Shred [S&P'16]**
    - **DACR 레지스터**를 통해 domain 단위로 접근 제어를 하므로, 메모리 접근 명령 자체를 변경할 필요가 없음
        - 접근 권한도 `shred_enter` → DACR = 11, `shred_exit` → DACR = 00 식으로 **단순 제어 가능**
    - 보안 정책은 **하드웨어 레벨(DACR)에서 강제**되므로, 사용자 코드가 이를 우회할 수 없음
        - DACR 변경은 privileged instruction이므로 **user-level code에서 직접 조작 불가**
    - ARM Domain은 **page 단위(`4KB`)**로 격리 가능 → fine-grained한 접근 제어

## 11주차: Hardware-assisted Software Security #2

> - Hardware-assisted Software Security [10,11]
> - ARM MTE 관련 코드 어떻게 할것인가 [11]

- **ARM BTI (Branch Target Identification)**
    - **CFI**를 HW로 지원하기 위한 HW 확장
    - jmp해서 실행한 첫번째 instruction이 무조건 `BTI`이어야 함
        - coarse-grained CFI
- **Intel CET (Control-Flow Enforcement Technology)**
    - **IBT(Indirect Branch Tracking)** (`endbranch`) + **shadow stack** (return address를 복사해서 보호)
    - FineIBT [RAID’23]
        - intel IBT 기반의 coarse-grained CFI를 개선해서 fine-grained CFI로 만들겠다
        - indirect call 하기 전에, special value를 넣어두고, 점프 후 special value를 빼서 `je` 체크
            - IBT의 `endbranch` 통과 이후에 체크를 한번 더 하는 거
                - IBT 체크해야 됨?? → 하는게 성능이 더 좋더라더라
    - CETIS [CCS’22]
        - CFI를 위한 Intel CET 기술로 **Intra-process Memory Isolation 구현하기**
            - Shadow stack이 있는 특수한 **shadow stack memory page**는 특수한 memory instruction으로만 접근 가능
                - Shstk Page에 isolated memory region을 둠 → 여기에 대한 접근은 `WRSSQ`, `WRSSD`만 가능
                - 근데 이 instruction의 속도가 너무 느림 → **write할 때, buffering을 둠**
- **ARM Pointer Authentication**
    - **Pointer Authentication Code (PAC)** = 포인터에 대한 해쉬값
        - 이걸 pointer의 앞부분에 넣어둠 (pointer representation을 아예 바꿈)
        - [56:63] can be used for MTE
        - Instruction: `PAC*` → 계산 , `AUT*` → 검증
        - ret addr를 `PAC*`으로 계산해서 stack에 넣어두고, function body 이후에 `AUT*`로 검증
    - PACStack [Security’21]
    - PACmem [CCS’22] (◆발표 논문)
    - PTAuth [Usenix '21]
        - PAC으로 UAF를 막자

- <span style="background-color:#e9d5b8">**ARM MTE (Memory Tagging Extension) ◆**</span>
    - **Lock**: memory region에 대한 Tag (16-byte memory block 당 4-bits씩 Tag 표시)
    - **Key**: stored in bits [59:56] of a pointer (포인터에 있는 4bit ID)
        - Temporal, Spatial Memory Safety
    - StickyTag[SP’24]
        - Tag가 제한되어 있으니까, Temporal, Spatial 모두 확률적으로 겹칠 수가 있다
        - 미리, tag가 할당된 heap, memory page를 할당해두고, malloc이 들어오면 재사용해서 주자
            - Spatial 에러는 탐지 가능하고, overhead가 줄어든다
    - ZomeTag [TIFS’23] (◆발표 논문)

    - PAN=1이면 일반 load/store로 user space 접근 불가
    - 사용자가 제어할 수 있는 주소 영역으로 커널이 잘못 접근하지 않도록 강제
- **LSU**: LSU 메모리 명령어를 사용하면 User mode에서 사용하는 것 같은 효과를 부여함 (e.g. `LDRT`, `STRT`)

- **TT**: 주소가 속한 MPU region Number 추출(하위 1byte) → `TT(addr) & 0x000000FF`

(page grouping → Privilege)
- **Domain + DACR**: 페이지 단위(=`domain`)로 접근 제어를 하되, TLB 업데이트 없이 HW기반의 `DACR`만 바꿔도 권한 변경 가능
- **Protection Keys + PKRU**: DACR과 유사하지만 유저레벨에서 접근 가능한 intel의 기능 → `WRPKRU`, `RDPKRU`
- **EPK**: Extended Protection Key → `EPT index (0–511)` + `pkey (1–15)` 조합으로 domain ID 구성

- **MTE** : 포인터에 tag 부여, memory region에 tag 검사 수행
